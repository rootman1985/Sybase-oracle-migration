# Sybase -> Oracle Migrator

Outil Java 17 / Maven pour migrer de gros volumes Sybase ASE vers Oracle par plages
de la première colonne (clé d'ID).

## Principe

- Connexion JDBC Sybase et Oracle.
- Lecture automatique des métadonnées des deux tables.
- Comparaison des colonnes et types.
- Première colonne utilisée comme clé de découpage.
- Lecture Sybase par plages `ID > last AND ID <= upper`.
- INSERT Oracle avec `PreparedStatement` et `executeBatch()`.
- Commit tous les `batch-size` lignes.
- Sauvegarde de progression dans `state/`.
- Mode `CHECK` pour valider les mappings avant migration.
- Mode `MIGRATE` pour exécuter la migration.
- Journal CSV des erreurs.

Le projet est volontairement générique : pour ajouter une table, on ajoute une ligne
dans `tables.csv`. Les colonnes sont découvertes par JDBC. Une correspondance manuelle
peut être ajoutée dans `column-mappings.csv` si les noms ne correspondent pas.

## Pré-requis

- Java 17+
- Maven 3.9+
- Driver Oracle JDBC `ojdbc11`.
- Driver Sybase ASE jConnect (`jconn4.jar`).

Le driver Sybase jConnect n'est pas inclus dans le projet. Placez le JAR fourni par
votre installation Sybase dans `lib/jconn4.jar`, puis lancez Maven avec l'installation
locale décrite ci-dessous, ou configurez votre propre repository interne.

## Configuration

Éditez `src/main/resources/application.properties`.

Puis `tables.csv` :

```
source_schema,source_table,target_schema,target_table,id_column,enabled
dbo,CDX_ADM_LOG_EXTRACT_DOC,REPORTING,CDX_ADM_LOG_EXTRACT_DOC,IdLog,true
```

`id_column` est optionnel : s'il est vide, la première colonne de la table Sybase
est utilisée.

### Taille des plages

`migration.range-size=10000`

Exemple :
- 0..10000
- 10000..20000
- etc.

Le programme ne suppose pas que les IDs sont continus.

### Batch Oracle

`migration.batch-size=1000`

Le programme lit jusqu'à `range-size` lignes puis envoie les INSERT Oracle par
batch de `batch-size`.

Pour des tables de 10+ millions de lignes, commencez prudemment avec :
- range-size = 10000
- batch-size = 1000

et ajustez après mesure.

## Commandes

Compilation :

```
mvn clean package
```

Vérification sans insertion :

```
java -jar target/sybase-oracle-migrator-1.0.0.jar CHECK
```

Migration :

```
java -jar target/sybase-oracle-migrator-1.0.0.jar MIGRATE
```

Une table particulière :

```
java -jar target/sybase-oracle-migrator-1.0.0.jar MIGRATE CDX_ADM_LOG_EXTRACT_DOC
```

## Reprise

La progression est enregistrée dans `state/<table>.state`.

Après un arrêt, le programme reprend à partir de la dernière borne validée.

Important : le programme commit une plage uniquement après succès de tous les
batches de cette plage. Une interruption au milieu d'une plage peut nécessiter
un nettoyage/reprise de cette plage selon la stratégie de chargement.

## Attention aux clés étrangères

La table d'exemple possède des clés étrangères vers :
- CDX_CANALDIFFUSION
- GDC_DOCUMENT
- CDX_ADM_LOG_EXTRACT_TYPE

Les tables parentes doivent donc être migrées avant cette table si les contraintes
Oracle sont actives.

## Identity Oracle

L'ID Sybase est une colonne IDENTITY et l'Oracle est `GENERATED BY DEFAULT ... AS
IDENTITY`. Le migrateur insère volontairement l'ID source afin de conserver les
identifiants historiques.

Après une migration d'une colonne identity Oracle, vérifiez que sa séquence
interne est positionnée au-dessus du MAX(ID) avant de laisser l'application créer
de nouvelles lignes. Le projet propose l'option `migration.sync-identity=true`;
testez-la d'abord sur une base de recette.

## Limites / adaptations futures

- Mapping de transformations métier spécifiques.
- CLOB/BLOB volumineux.
- Désactivation/réactivation automatique des contraintes.
- Parallélisation contrôlée par table/plage.
- Reprise idempotente avec clé primaire.
- Rapport global CSV.
